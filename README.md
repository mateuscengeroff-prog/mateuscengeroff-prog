## About

I'm a computer science student at Unisinos in southern Brazil and, since August 2026, a software development intern at CABERGS. At work I build and maintain web applications with C#, ASP.NET Core and Razor Pages: responsive layouts, forms, REST API data in the interface, functional testing and bug fixing, shipped as small, focused Git changes.

Outside work I pick projects that are a little too big for me, because that's where I learn the most: a community web app built with a team, a multiplayer Roblox game, and a local tool that keeps AI coding agents on a short leash. A lot of that work is AI-assisted, so I've had to get good at the parts that stay human: deciding what to build, writing clear specs, reviewing diffs, and not calling anything done before it's tested.

I studied English in Toronto at ILAC and volunteer as a buddy for international students at Unisinos. In the long run I want to work as a software engineer abroad. Germany is high on my list, and I'm open to other countries too.

A local dashboard that queues coding tasks, gives each one an isolated Git worktree and holds every change for human review.

**Status:** In development. Core MVP is on main. Review, isolation and recovery work sits in draft pull requests. No real AI agent is enabled yet.  
**Stack:** Python, FastAPI, SQLite, Git worktrees, pytest, GitHub Actions

<details>
<summary><b>Case study</b></summary>

**What works today**

- Task queue with status tracking and logs, stored in SQLite
- One branch and one Git worktree per task, so tasks never share a working copy
- Local-only API bound to 127.0.0.1, with no automatic push, merge or deploy
- Test suite running in CI on both Linux and Windows against a simulated agent

**My role**

Personal project. I own the product direction, architecture decisions and safety rules, and coordinate AI-assisted implementation through draft pull requests that I review before anything reaches main.

**Engineering challenges**

- Letting an agent change code without ever giving it a path to main
- Recovering cleanly when a task process fails halfway through
- Keeping simulated CI results separate from real validation on a physical machine

**Code:** private repository. Happy to walk through it in an interview.

</details>
